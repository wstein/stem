= Cross-Cutting Concepts
:page-layout: default

Use this chapter for concepts that apply across multiple building blocks.

== Security and HTML Escaping

Stem is **secure by default**: `{{ expression }}` output is **automatically HTML escaped** to prevent XSS attacks.
Use `{{{ expression }}}` for raw output only when you know the content is safe.

Escape modes can be configured globally via `.stem.config.json` or per-call:

* **HTML escaping (default)** — Prevents XSS attacks
* **Raw output (`:none`)** — Use with caution only for trusted content
* **Other modes** — `:xml`, `:json`, `:url`, or custom escape functions

Keeping the rendering model explicit makes security-sensitive formatting decisions visible at the call site.
Callers must treat all dynamically selected templates and user-provided context as untrusted.

== Execution Modes: Restricted vs. Unrestricted

Stem enforces control over arbitrary Elixir expression execution via the `allow_elixir_expressions` flag:

* **`allow_elixir_expressions: false` (default, recommended)** — Restricts templates to structured Stem expressions, literals, helpers, and variable paths. Forbids arbitrary Elixir code. Protects against Server-Side Template Injection (SSTI). This is the required mode for all production templates.

* **`allow_elixir_expressions: true`** — Allows arbitrary Elixir expressions. Maximum flexibility but should only be used for development and local experiments when the template source is entirely trusted and controlled by your team. Passing `allow_elixir_expressions: true` serves as a visible code-review flag.

Runtime evaluation APIs (`Stem.Unsafe.eval_string/3` and `Stem.Unsafe.eval_file/3`) default to `allow_elixir_expressions: false`, requiring explicit opt-in to use `allow_elixir_expressions: true`.
If you feel forced to enable arbitrary expressions in production, this indicates an architectural flaw: business logic is leaking into the presentation layer and should be refactored into helpers or backend services.

== Helper Capability Groups

Beyond restricting arbitrary Elixir code, Stem also enforces capability management for helper functions.
A template has access only to the helpers it explicitly needs, reducing Server-Side Template Injection (SSTI) attack surface through **principle of least privilege**.

The secure minimum (`Stem.Helpers.Minimum`) is always available and contains only essential helpers for XSS protection and output formatting.
Complex data operations (filtering, sorting, grouping, transformation) are organized into optional capability groups:

* `Stem.Helpers.Strings` — Text manipulation
* `Stem.Helpers.Collections` — Data transformation and filtering
* `Stem.Helpers.Predicates` — Boolean predicates for conditionals

Templates must explicitly declare which groups they need via the `:helper_groups` parameter:

[source,elixir]
----
Stem.Unsafe.eval_string(template, assigns: data, helper_groups: [Stem.Helpers.Collections])
----

Or via `.stem.config.json` defaults:

[source,json]
----
{
  "helper_groups": "Stem.Helpers.Collections,Stem.Helpers.Strings"
}
----

*Rationale:* In an SSTI attack, an attacker can chain powerful operations (map, filter, group_by) to extract internal state or manipulate data.
By restricting access to only approved groups, Stem minimizes the "gadget chains" available for exploitation.
The requirement to explicitly declare which operations are needed makes dangerous choices visible during code review.

== Explicit Data Boundaries

Stem preserves an explicit boundary between data and templates at all levels.
In the CLI, the command contract differentiates between file-backed JSON (`mix stem data.json template.stem`) and stdin-piped JSON (`echo '{}' | mix stem template.stem`), avoiding implicit ambiguity parsing strings versus files.

== Whitespace Control

Stem provides declarative, tag-level whitespace control using the `~` character.
Whitespace logic allows adjusting spacing around rendered content without littering source files with unreadable formatting:

* `{{~ ... ~}}`: Trims literal whitespace symmetrically before and after the tag.
* `{{~ ... }}` and `{{ ... ~}}`: Trims whitespace precisely on the given side (one-sided trim).
