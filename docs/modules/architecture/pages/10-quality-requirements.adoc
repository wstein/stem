= Quality Requirements
:page-layout: default

Document the quality attributes that matter most for this system.

== Quality Goals

Reliability, performance, security, and maintainability are the primary attributes for a template compiler that turns untrusted-adjacent input into executable code.

== Testing Strategy

Stem combines example-based unit tests with property-based fuzzing of the parse and compile pipeline.

* **Unit and regression tests** cover the tokenizer, parser, compiler, expression translator, helpers, and CLI with concrete inputs and expected outputs.
* **Property and fuzz tests** (`test/stem/fuzz_test.exs`, using `StreamData`) generate random but structurally valid template sources and assert that `Stem.Expression.parse/1`, `Stem.Parser.parse/2`, and `Stem.Compiler.compile/2` never raise — they must return `{:ok, _}` or a structured `{:error, ...}` tuple. This exercises edge cases such as deeply nested blocks, recursive partial expansion, and pipeline-argument escaping that hand-written examples miss.

Generators are bounded by a `depth` parameter so that generated trees stay finite. Because `StreamData` generators are constructed eagerly, recursive generators must bottom out at depth 0 and defer recursive branches behind lazy `bind`/`constant` combinators; otherwise the generator tree is built forever and the test hangs at construction time rather than failing.

== Coverage Gate

Line coverage is held at or above the threshold defined in `CLAUDE.md` (90%). API-affecting changes must update source docs and regenerate derived docs with zero drift.
