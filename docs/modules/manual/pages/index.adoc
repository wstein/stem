== Command Line Interface (CLI)

Stem ships with an explicit, file-centric CLI that allows you to easily format and execute templates from your shell.

=== Formatting Templates

To format your `.stem` template files, use the `mix stem.format` task:

[source,sh]
----
mix stem.format "lib/**/*.stem"
mix stem.format --check-formatted path/to/template.stem
----

=== Rendering Templates

The CLI supports strict file or standard input models for binding data, modeled after standard Mustache CLI tooling conventions.

*File-backed Data and Template:*
When providing two positional arguments, the first specifies a JSON data file and the second points to the `.stem` template file:

[source,sh]
----
mix stem data.json template.stem
----

*Standard Input Interpolation:*
When providing a single positional argument, the CLI reads the JSON object from the pipeline standard input and applies it to the template:

[source,sh]
----
echo '{"name":"Nina"}' | mix stem template.stem
----

By isolating the data into standalone files or pipes, there is no ambiguity parsing raw strings vs files on the command line.

=== Execution Modes

The CLI supports two execution modes via the `--allow-elixir-expressions` flag:

*Restricted Mode (default):*
[source,sh]
----
# Restricts templates to structured Stem expressions only
echo '{"name":"Nina"}' | bin/stem template.stem
----

*Unrestricted Mode:*
[source,sh]
----
# Allows arbitrary Elixir expressions — development only
echo '{"a":1,"b":2}' | bin/stem template.stem --allow-elixir-expressions
----

Use restricted mode (the default) for all production templates and when working with untrusted or user-generated templates.
Only use `--allow-elixir-expressions` for local development and experiments on templates you fully control.

== Runtime APIs

Stem provides runtime evaluation APIs for dynamic template compilation:

[source,elixir]
----
# Restricted by default — structured Stem expressions only
Stem.Unsafe.eval_string("Hello {{name}}", assigns: [name: "Nina"])

# Explicit opt-in for arbitrary Elixir — development/trusted sources only
Stem.Unsafe.eval_string("{{a + b}}", assigns: [a: 1, b: 2], allow_elixir_expressions: true)
----

Always use `allow_elixir_expressions: false` (the default) for production templates.
Only pass `allow_elixir_expressions: true` when the template source is entirely controlled by your team and arbitrary code execution is necessary.

For full API reference, see xref:architecture:index.adoc[Architecture] documentation.

== Security Best Practices

* **Always use `allow_elixir_expressions: false` in production.** It is the default for a reason.
* **Never execute user-generated templates.** If you must, ensure they are validated and safe first.
* **Use HTML escaping by default.** `{{ expression }}` is escaped; use `{{{ expression }}}` only for trusted content.
* **Inject all data via `assigns`.** Do not allow templates to read environment variables or access global state.
* **Register custom helpers instead of enabling arbitrary expressions.** Helper functions keep business logic out of templates.
