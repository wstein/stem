= 00004 Native Compiler Minutes and Specification

Date: 2026-05-21

Team: University Professor, Software Engineer, Technical Writer

Goal: replace the EEx-backed compilation path with a native `{{ }}` compiler so Stem owns its tokenizer, parser, AST, and code generation.

== Meeting Minutes

. Problem statement confirmed: templates were rewritten into EEx text and run through the EEx tokenizer and compiler, which leaked EEx semantics, escaping markers, and error messages.
. Decision: build a native pipeline `tokenizer -> parser -> AST -> compiler` that emits Elixir AST directly.
. Decision: drop the EEx surface entirely, including the `<%= %>` tag family, the `Stem.Engine`/`Stem.SmartEngine` behaviour and custom engines, the EEx tokenizer (`Stem.tokenize/2`), and the `:engine`, `:trim`, and `:parser_options` options.
. Constraint: preserve the `{{ }}` language already exercised by the test suite (expressions, raw output, comments, raw quotation, `#if`/`#unless`/`#each`/`#with`, `else`, partials, helpers, `this`/`@index`/`@key`, and `../` parent access).
. Constraint: keep the compile-time-only security model; runtime evaluation stays disabled.

== Specification

=== Pipeline

- `Stem.Tokenizer` scans source into structural tokens with line and column metadata.
- `Stem.Parser` matches block open/else/close tokens into a `Stem.AST`, expands partials inline with a recursion guard, and reports structural errors.
- `Stem.Compiler` lowers the AST into quoted Elixir; `Stem.Expression` translates the contents of each tag, and `Stem.Runtime` resolves assigns at runtime.

=== Non-Goals

- No backward-compatibility layer for the removed EEx syntax.
- No Handlebars-style standalone whitespace control yet; the `:trim` option was removed with the EEx tokenizer.

== Implementation Summary

- Added `Stem.Tokenizer`, `Stem.Parser`, `Stem.AST`, `Stem.Compiler`, `Stem.Expression`, and `Stem.Runtime`.
- Removed the EEx compiler, engine, smart engine, and the string preprocessor.
- Rewrote the public surface and module documentation in `lib/stem.ex`.
- Added a symmetric `helpers` no-op in the function macros and marked loop bindings as generated to keep compilation warning-free.
- Repaired the standalone-checkout coverage guard so `mix test --cover` runs.

== Validation

- Full suite green via `mix test` (including doctests).
- Line coverage is 99% via `mix test --cover`, above the 98% threshold.

== Next Steps
