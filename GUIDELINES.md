# Stem Guidelines

Use semantic versioning for all releases.  
Follow conventional commits for git messages.  
Write documentation with one sentence per line to ease diffs.  
Maintain a top-level GFM file summarizing key rules.  
Keep detailed docs in AsciiDoc under docs/.  
Treat README.md as a 101 guide for junior developers.  

Introduce examples and tests at each stage of development.  
Keep documentation, README, checklists, and manuals synchronized.  
Commit after each significant change with clear conventional commit messages.  
Avoid backwards compatibility; focus on clean breaks in PoC/MVP.
